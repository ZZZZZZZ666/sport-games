# 本轮改进与下一步

本轮按 roadmap 的推荐顺序推进 M1，基于 `7082240`。未新增 M2 运动项目，也未把整个路线图标成完成。

## 已实现

| 功能 | 行为与实现入口 |
|---|---|
| 玩家档案 | `core/profiles.gd` 保存四个稳定玩家槽的名字、颜色、角色；滑板、滑雪、篮球使用所选外观 |
| 手机昵称 | 手机设置可输入昵称；WebSocket `profile` 与 roster `profile_name` 同步；昵称是纯文本，富文本显示处转义 |
| 手柄管理 | 主菜单直接扫码、查看电量、分配 P1–P4、归零和校准；设备与二维码动态更新 |
| 个人最佳 | `core/records.gd` 按项目、地图、玩家保存最佳，结算与主菜单展示；机器人及调试规则不入榜 |
| 派对大赛 | `core/tournament.gd` 管理 3–6 项、固定玩家槽、名次积分、并列名次、防重复计分和最终二维领奖台 |
| 菜单设置 | 复用暂停设置，支持画面、声音、语言及色弱友好玩家配色；音频总线本来已实现，本轮补入口和回归测试 |
| 致谢 | 游戏内来源摘要，对应已有素材说明；不替代未来二进制发行的完整许可文件 |
| 新手教学 | 六项目先看手柄动画、再做真实输入练习，通过后才允许准备；按玩家 / 项目持久化，可从大厅或暂停菜单重练 |
| 自动检查 | 存档读回与派对规则测试、三个真实场景的连续切换测试、完整回合冒烟脚本及 GitHub Actions 配置 |

四个档案是 P1–P4 本地槽，不是无限数量的用户账号。更换名字不会创建新身份，旧纪录仍对应该槽。普通单项比赛可随时退出；派对赛的下一项会等待原参赛槽全部连接并准备。

## 建议优先级

1. **先完成验证闭环**：同步余下素材，六项目 × 2 / 4 人完整回合，再做三种手柄的长局、断线和重连验证。补一张截图总览图。当前派对总领奖台是公共二维界面，未来可接统一三维演出。
2. **补单人体验并验证教学**：教学框架已接六项目，下一步用手机 / Regina 校准提示和阈值；正式电脑对手提供三档难度；每项目设三个挑战目标与星数。先选一个项目打通，再推广。
3. **完成音频和演出**：选择可核实来源的 CC0 菜单 / 大厅 / 胜利音乐；把滑板、滑雪、篮球重复的开场、回放和领奖台抽成公共模块。主菜单还缺预览图。
4. **用测量推进性能**：固定参考硬件、分辨率、路线和机器人种子，记录 CPU / GPU 帧时间；据结果调整分屏阴影、LOD 和 FSR，不用未测数据宣称达到 60 fps。
5. **提高存档与构建可靠性**：增加存档版本、迁移、备份和损坏恢复；锁定 Python 依赖与工具链版本；建立 Windows 原生失败日志 / 转储收集。发布前重新跑许可和素材完整性审查。
6. **最后扩内容和发行**：先写高尔夫的挥杆、推杆与计分设计；再做其他新项目。补 Godot 导出、hub 打包和便携包。安装包与发布范围确定后再做渠道配置。

后续迭代应保留上述验证边界；完整回归通过后再更新相应 TODO 状态。
